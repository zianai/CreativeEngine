# Controlled single-host operations

Scope: one trusted local operator, one machine, separate CreativeEngine SQLite/assets/receipts. This is not a public or multi-tenant service. TradeCase and LaunchCase use HTTP; neither may open this database. No production deployment, provider payment or remote Git write was performed.

Start E1 from this checkout after building Studio. Use a fresh directory, a dedicated local access token, and a sanitized environment containing only PATH/HOME/TMPDIR plus CREATIVE_DATA_DIR, CREATIVE_API_TOKEN, PORT and ALLOW_TEST_LIVE=off. Run `node_modules/.bin/tsx scripts/p10-local.ts`. It binds 127.0.0.1, defaults to port 4310, registers only Mock, and rejects a live flag, OpenAI credential or pinned paid grant. Never load the original `.env`. The synthetic token authenticates local access only; it is not a paid-provider grant. Studio's “连接本地服务” exchanges it for an in-memory one-hour HttpOnly/SameSite=Strict cookie. Restart or token rotation invalidates that session. Raw tokens are not put in browser storage. Missing auth configuration fails protected routes closed. HTTP remains inside loopback; `ops/staging/Caddyfile` is an optional local TLS template. The executed TLS smoke uses an ephemeral certificate and explicit CA trust in the test client; it does not claim a publicly trusted certificate or Caddy deployment.

Use `/v1/health`, `/v1/operations/status` and durable `/v1/events` with Last-Event-ID. Operations status reports queued/running/reconciling/vision uncertainty/failures without project content. Alert on reconciliation, uncertain Vision and failures. Do not turn an alert into a retry. The write quota defaults to 120/min per service; reads in the measured fixture are not a production latency SLA. Limit upload bytes to the existing 20 MiB API boundary; SVG, remote URL and arbitrary file-path imports are unsupported. Set `CREATIVE_WRITE_RATE_LIMIT` only within 1..10000. This is not distributed rate limiting.

Stop all HTTP, CLI, MCP and worker writers before backup. A human-visible `--writers-stopped` flag is a prerequisite, not proof that other processes stopped. Run `node_modules/.bin/tsx scripts/p10-backup.ts backup SOURCE NEW_SNAPSHOT --writers-stopped`. The helper rejects queued/running/QA jobs, new writes observed during the copy, symlinks and existing targets. It uses SQLite's backup API and hashes copied assets, provider receipts, attempt receipts and exports. Preserve both database and files; never copy only SQLite or clear unknown attempts.

Restore with `node_modules/.bin/tsx scripts/p10-backup.ts restore SNAPSHOT NEW_DATA_ROOT --writers-stopped`. It verifies declared file hashes and safe paths, restores only into a new directory, relocates exact JSON `path` fields, checks SQLite integrity and asset/export hashes, and retains receipt hash/attempt bindings. Start isolated E1 to inspect the restored copy before adopting it. Migration version 1 is idempotently opened on this copy; rollback is selecting the previous whole snapshot, never production schema downgrade. Tested restoration covers completed synthetic assets plus an unknown simulated paid attempt. Same-host new-directory recovery is tested; cross-machine, power-loss/fsync durability, concurrent-writer recovery, remote object storage and RPO/RTO SLA are not established.

For ambiguous provider outcomes, retain `reconciling` and unknown actual costs. Inspect operator-owned receipts/billing only after new explicit read authorization. Reconciliation requires a named operator and provider evidence; never infer “no charge” from timeout or missing usage. Do not delete reservation rows to unblock a run. Native remote batch remains disabled in the normal per-image Worker; its provider declaration does not establish tested remote-batch recovery.

Optional E2 image harness: `node_modules/.bin/tsx scripts/p9-paid-worker.ts --preflight DATA_ROOT BATCH_ID`; `--execute-once` is a separately authorized action and was NOT executed against a real provider. It requires a fresh pinned operator grant, data-read capability and exact `worker_subject` (data_root, batch_id, project_id, plan_id, task_id), one queued task with no attempts, matching plan/rights/provider/input hashes and one image/request/attempt budget. Provider itself revalidates and reserves at the last external-call boundary. Preflight does not authorize execution. No automated approval/export, revisions, native batch or Vision is enabled by this harness. A paid Vision run requires its own separately reviewed scope/receipt/cost; fresh E2 Vision remains BLOCKED_EXTERNAL.

Read-only evaluation export: `scripts/p8-export-evaluation.ts --synthetic-fixture NEW_OUTPUT` creates its own new temporary Mock workspace and never accepts an existing root as “synthetic”. Existing workspaces require `DATA_ROOT BATCH_ID NEW_OUTPUT public|redacted_business|sensitive_business`, a fresh pinned data-read grant and exact `evaluation_subject` (data_root, batch_id, project_id, plan_id). Its output must remain in the private operator-record directory. It opens SQLite read-only after subject validation. Plan hash is SHA256(JSON plan); input hash is SHA256(JSON {sources:[{id,sha256}] sorted by id, truth}); rights hash is SHA256(JSON ordered source rights fields); provider configuration is the batch snapshot hash. Rights and file hashes are rechecked. Returned provider identity must be hidden by the separate blind-review harness. Metadata export grants no commercial rights or acceptance.

Deletion/retention: stop writers, identify the exact disposable E1 directory from the run record, then remove only that directory. This run deletes only its own temporary fixtures. Deleting authorized business data, backups, or operator ledgers requires the owner's retention decision; no destructive general-purpose endpoint was added. Never rewrite P7 historical evidence.
